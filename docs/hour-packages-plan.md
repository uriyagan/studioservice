# ניהול חבילות שעות — תוכנית מימוש

> מסמך עיצוב לשדרוג ניהול חבילות השעות מ"מספר סקלרי גמיש" ל"מחסניות נפרדות" עם מחזור חיים, תור FIFO, ומגבלה קשיחה. נכתב ביולי 2026.

## הבעיה

היום "חבילת שעות" אינה ישות — היא רק העמודה `projects.total_hours_allocated` (מספר בודד). מכאן נובעות כל הבעיות:

- **אין מחסנית קשיחה** — עריכת שעות באדמין *דורסת* את המספר; רכישת Stripe *מוסיפה* אליו. אין חבילות נפרדות עם התחלה/סוף.
- **אין מגבלה** — שום בדיקה לא משווה ניצול מול התקציב. ה־view `project_stats` עוטף את היתרה ב־`greatest(...,0)` ובכך *מסתיר את המינוס*. אפשר לעבוד עד אינסוף.
- **אין היסטוריית חבילות** — יש `purchases` (קבלות Stripe) אבל אין מחזור חיים של חבילה.

## עקרון הליבה: ledger נגזר, ללא drift

שומרים על הפילוסופיה הקיימת — `time_logs` הוא מקור האמת היחיד, הצריכה **נגזרת** ולא נשמרת כמונה. רק מחלקים את הצריכה בין חבילות ב־FIFO:

- **סך הצריכה של פרויקט** = סכום כל מקטעי `time_logs` (כולל מקטע רץ שנספר עד `now`).
- **חבילה שהסתיימה מלאה תמיד** (נחסום בדיוק על הגבול) ⇒ `depleted_hours = Σ שעות של חבילות depleted`.
- **צריכת החבילה הפעילה** = `סך_הצריכה − depleted_hours`; **היתרה** = `active.hours − צריכה_פעילה`.
- שדות מחזור החיים (`status`, `activated_at`, `closed_at`, `activated_by`, `source`) נשמרים כאירועים — לא ניתנים לגזירה.

**שינוי סמנטי מכוון:** היום מנוכה רק זמן על משימות *שהושלמו*. מעכשיו נספר את **כל** הזמן הרשום (רץ + מושהה + הושלם) — אחרת אי אפשר לאכוף מגבלה בזמן אמת.

## החלטות שנסגרו

1. **חריגה באמצע טיימר רץ** → עצירה מיידית על הגבול + מייל לאדמין האחראי על המשימה.
2. **תור FIFO** — חבילה פעילה אחת; נוספות ממתינות ומופעלות אוטומטית.
3. **תפוגה לפי שעות בלבד** — אין תוקף קלנדרי.
4. **מייל הוספת חבילה ע"י הצוות** — תבנית נפרדת חדשה.
5. **מקור בצד הלקוח** — תגית בסיסית בלבד: "רכשת" מול "נוספה ע"י הצוות".
6. **הקמת חבילה ע"י אדמין** — בלי בחירת מקור; מסומן אוטומטית `source='studio'`.
7. **זמן ידני שחורג מהיתרה** — נדחה עם הודעה (בלי פיצול אוטומטי ב־MVP).
8. **cron reconcile** — job מתוזמן ב־Cloudflare כרשת ביטחון.

## מודל נתונים

טבלה חדשה `project_packages` (מופע חבילה לפרויקט, נפרד מ־`hour_packages` שהוא קטלוג המכירה):

| עמודה | הערה |
|---|---|
| `source` | `'client_purchase'` \| `'studio'` |
| `hours` | תכולה |
| `status` | `'queued'` \| `'active'` \| `'depleted'` |
| `activated_at` / `closed_at` | אירועי מחזור חיים |
| `activated_by` / `purchase_id` / `note` | מטא־דאטה |
| `notified_half` / `notified_depleted` | דגלי סף **פר חבילה** (מחליף את ההאק שעל הפרויקט) |

אילוץ: אינדקס ייחודי חלקי `unique(project_id) where status='active'`. RLS: לקוח קורא את שלו (`client_id`/חברות), כתיבה לאדמין בלבד. `projects.total_hours_allocated` הופך למיותר — נשאר זמנית, נמחק ב־Phase 7.

## אכיפה

**שומרי סף (חוסמים מראש):** `startTimer`/`quickStartTimer`, `addManualTime`, `adjustTaskTime` — נחסמים אם אין חבילה פעילה עם יתרה.

**עצירה בזמן אמת — שתי שכבות:**
1. *צד לקוח:* הטיימר סופר לאחור וברגע 0 קורא ל־`enforcePackageLimit` שסוגר את המקטע על הגבול.
2. *צד שרת (`reconcileProject`):* נקרא מ־`closeActiveSegment`, מטעינת עמודי אדמין/פורטל, ומ־cron. מחשב את חותמת הזמן המדויקת של חציית הגבול, קוצץ את המקטע הרץ, מסמן את החבילה `depleted`, משהה את המשימה, מפעיל את הבאה בתור, ושולח מייל לאדמין האחראי.

ריטיינר/הקמה — פטורים מאכיפה.

## סדר פיתוח

0. **סכימה** — טבלה + אינדקסים + RLS + view חדש + backfill *(מיושם ידנית ב־Supabase)*.
1. **שכבת נתונים** — טיפוסים, `getActivePackageState`, `activateNextPackage`, `reconcileProject`.
2. **מסלולי כתיבה** — `createPackage` (אדמין), webhook→חבילה, ניקוי `updateProject`, `createProject`.
3. **אכיפה** — שומרי סף + עצירה חיה + hooks ל־reconcile + cron.
4. **UI אדמין** — `PackagesPanel`, `CreatePackageForm`, שינוי `ProjectRow`, מצבי טיימר חסום.
5. **UI פורטל** — דשבורד, עמוד חבילות, היסטוריה, מצב "אין חבילה פעילה".
6. **מיילים** — `package_added_studio`, `package_ended_admin`, מעבר דגלי סף פר־חבילה, מילוי `hours_added`.
7. **ניקוי** — מחיקת `projects.total_hours_allocated`.

## מיגרציה / backfill

- לכל פרויקט־שעות: חבילה `active` אחת בגודל `total_hours_allocated`, `source='studio'`, `activated_at=created_at`. הקבלות ההיסטוריות (`purchases`) נשארות; לא משחזרים מהן חבילות.
- **מקרה חריג יחיד — barak-188.com:** שילם חיצונית על 40 שעות. החבילה הישנה נסגרת (`depleted`) והיתרה העודפת עוברת אוטומטית לחבילת 40 השעות החדשה (`source='studio'`). מטופל במיגרציה נפרדת `2026-07-24_barak_external_package.sql`.
